# Shape Packing Solver (二维形状装箱求解器)

这是一个用于解决二维不规则形状打包（装箱）问题的求解器。主要针对《胜利女神：妮姬》（NIKKE）等活动小游戏（如生化危机联动、方舟游侠活动等）的武器装箱问题，也可用于其他类似的二维形状打包布局问题。

本项目提供了两种实现版本：
1. **[纯前端网页版（推荐）](#一纯前端网页版)**：无需安装，即开即用，直接在浏览器中进行求解。
2. **[Python 本地版](#二python-本地版说明)**：基于 Google OR-Tools 的 CP-SAT 约束求解器，支持 GUI 和 CLI 两种模式。

---

## 一、纯前端网页版

网页端是一个纯前端实现的交互式应用，支持在 9x9 容器内进行网格涂抹、自定义形状数量、设置锁定（必须放置）以及是否旋转等选项。

### 🔗 在线体验网址
**[https://solver.nikke.cc](https://solver.nikke.cc)**

### 🛠️ 技术栈与算法实现
* **核心框架**: React + TypeScript + Vite + Vanilla CSS。
* **多线程计算**: 使用 Web Worker 执行求解算法，防止耗时较长的搜索过程导致浏览器主线程卡死或 UI 冻结。
* **算法设计**: 
  - 采用**以单元格为中心的深度优先搜索 (Cell-Centric DFS) 回溯算法**。
  - **旋转去重**: 对允许旋转的形状，在 0°、90°、180°、270° 四个方向上进行旋转变换并做空间去重，排除对称图形的多余朝向。
  - **位置预计算**: 针对每个合法的网格单元，预先计算所有形状在不同朝向下的可行放置方案（Candidates），以此加快回溯时的碰撞检测。
  - **强剪枝优化**: 在搜索的每一步实时估算最大可能获得的面积（当前面积 + 剩余可用空格与剩余形状面积的较小值）。若估算值不大于当前已找到的最佳面积，则提前回溯，以极高效率找到最优解。

## 二、Python 本地版说明

基于 Python 开发的本地求解器，使用约束规划（CP）技术提供极高效率的全局最优解。

### 📥 编译包下载
* **打包好的 `.exe` 文件下载地址**: [GitHub Releases](https://github.com/entishl/nkrbehgamehelper/releases)
* **自定义形状**: 可直接修改 `shapes.json` 文件，或者在 GUI 界面的“形状管理”中进行新增、修改和删除。

### ✨ 功能特性
* **双重接口**: 既有适合快速交互的 Tkinter GUI 图形界面，也有适合脚本调用的 CLI 命令行模式。
* **自定义容器**: 支持在 GUI 中通过点击 9x9 网格自定义容器布局（黑色为阻挡单元，白色为可用单元）。
* **旋转与去重**: 求解器自动测试 0°、90°、180°、270° 朝向，自动剔除对称旋转。支持勾选禁用旋转。
* **锁定机制**: 允许在 GUI 中通过锁形图标 (🔒) 强行锁定某些形状，保证其必须出现在最终方案中。
* **高效双阶段求解**: 采用“可行性探索 -> 面积最大化”的双阶段求解机制，优先在数秒内快速寻找完美覆盖解。

### 💻 系统要求
* Python 3.12 (或更高版本)
* Tkinter (通常随 Python 默认安装)
* Google OR-Tools

安装依赖：
```bash
pip install ortools
```

### 🔨 自编译指南
如果您想自行编译为 `.exe` 可执行文件：
```bash
pip install ortools pyinstaller
pyinstaller gui.spec
```
编译完成后，生成的可执行程序位于 `dist/gui` 目录下。分发时只需将整个 `dist/gui` 文件夹压缩即可，在 `dist/gui` 下修改 `shapes.json` 依然能被程序读取。

### 🚀 如何使用

#### 1. GUI 模式
运行图形界面：
```bash
python gui.py
```
**界面指南**:
1. **容器形状**: 在左侧的 9x9 网格中单击单元格，以定义可用于打包的区域。白色可用，黑色为阻挡。
2. **形状数量**: 使用输入框和上下按钮指定每种形状的期望打包数量。
3. **锁定形状**: 点击形状旁的锁图标 (🔒) 以强制该形状被包含在最终解中。
4. **允许旋转**: 若取消勾选，则形状保持默认朝向（0°）。
5. **自定义形状**: 可以在“形状管理”弹窗中增删改形状的网格结构。
6. **时间限制**: 限制求解的最大计算秒数。
7. **计算**: 点击 "Calculate" 按钮开始求解，求解结果将实时渲染在右侧画布上。

#### 2. 命令行 (CLI) 模式
通过参数指定需求并运行 `main.py`：
```bash
python main.py --shape_counts "square=2,T=1" --board_size "10,10"
```
**参数说明**:
* `--shape_counts` (必需): 指定每种形状的名称和数量，用逗号分隔。如 `"square=2,T=1"`。
* `--board_size` (可选): 棋盘的长宽。默认 `"10,10"`。
* `--shapes_file` (可选): 自定义形状定义 JSON 的路径。默认 `shapes.json`。
* `--no_rotation` (可选): 禁用旋转。

### 🔬 技术实现细节
本地版将该二维装箱问题建模为**约束规划 (Constraint Programming)** 问题，并通过 Google OR-Tools **CP-SAT** 求解器进行求解：

1. **旋转朝向生成**: 自动生成 0°、90°、180°、270° 朝向，规范化坐标至左上角 `(0, 0)`。通过字符串表示比对自动去除对称朝向。
2. **合法位置预过滤**: 预计算并在内存中缓存每个形状所有有效朝向在棋盘上的合法摆放格点，大幅降低求解器的变量空间。
3. **CP-SAT 模型建模**:
   * **决策变量**: 
     - 每个候选放置（位置+朝向）关联布尔变量 `b_pos`。
     - 形状是否使用关联布尔变量 `is_used`。
   * **放置约束**: 
     - 每个形状最多只能选择一个位置及朝向放置（`is_used == sum(b_pos)`）。
   * **不重叠约束**: 
     - 对每个允许放置的网格格点，所有覆盖该格点的放置布尔变量之和在普通模式下 $\le 1$（使用 `AddAtMostOne`），在满覆盖模式下 $= 1$（使用 `AddExactlyOne`）。
   * **对称性破坏**: 
     - 在棋盘具有对称性且条件安全时，通过限制最大面积的锚点形状仅能在棋盘半边放置来裁剪搜索空间。
     - 对相同名字的形状添加排序约束，避免等价位置的冗余搜索。
4. **双阶段求解**: 
   - **第一阶段 (Feasibility Pass)**: 在极短的时间内（默认最多 2 秒），以寻找可行解为目标，通过强加完美解约束（如强制放置所有形状或填满棋盘）快速探测完美解，若找到则直接返回，大幅缩减简单排布的求解时间。
   - **第二阶段 (Optimization Pass)**: 若第一阶段超时或无解，重置模型并以最大化已放置的形状总面积（`sum(shape.area * is_used)`）为目标函数进行求解。
